## 1. Background

- After the newer PT v2 path was merged, the canonical top assembly temporarily moved to [`rtl/pt_top_v2.v`](../../../rtl/pt_top_v2.v) before converging back to [`rtl/pt.v`](../../../rtl/pt.v).
- The older `20260413` PASS artifacts predated `ce1d907` and could not be treated as a valid baseline for the new RTL.
- The first reproduced failures all appeared on the first `MATMUL` following `QCFG` in:
  - `smoke_4x4`
  - `smoke_8x8`
  - `extended_balanced_mix_4x4_seed10`

## 2. Initial Symptom

- Simulation stalled around `215 ns`
- `ctrl` had already been accepted
- forward progress stopped before a stable downstream request/response chain completed

The first pass of debugging showed:

- the command had already entered the `MATMUL` path
- later `dma_req` activity did not continue as expected
- the result directory contained older artifacts that could easily hide the new failure if used as a baseline

## 3. Root-Cause Chain

### 3.1 RTL Combinational Feedback In `PT_MALLOC`

[`rtl/pt_malloc.v`](../../../rtl/pt_malloc.v) contained allocator-side combinational feedback:

- `cmd_a_len/cmd_b_len` influenced `a_alloc_ok/b_alloc_ok`
- `a_alloc_ok/b_alloc_ok` then fed back into command-side legality/allocation decisions

Verilator reported this explicitly as `UNOPTFLAT` circular combinational logic.

### 3.2 cocotb Environment Follow-Up Issue

[`sim/cocotb/tests/pt_blackbox_env_v2.py`](../../../sim/cocotb/tests/pt_blackbox_env_v2.py) was not clearing stale `expected_dma_loads` after an error `ctrl_resp`, which later caused randomized and extended runs to fail with `dma_req kind mismatch`.

The environment also had a race when `ctrl_resp` and `m_dma_req` landed in the same cycle:

- the export agent could run before the reference model had committed the successful plan
- that produced `no ready M buffer available for export`

### 3.3 Reference-Model Commit Timing Bug

[`sim/cocotb/tests/pt_model_v2.py`](../../../sim/cocotb/tests/pt_model_v2.py) was advancing allocator pointers during `issue_matmul`, `issue_matadd`, and `issue_load`, instead of only after the transaction had actually committed.

That polluted later allocation state:

- `wrong_tuser`
- export errors
- and other non-committed failures

could still consume modeled capacity and trigger false later rejects.

### 3.4 Over-Optimistic Randomized Branching

[`sim/cocotb/tests/test_pt_randomized_cases.py`](../../../sim/cocotb/tests/test_pt_randomized_cases.py) assumed the `export_error` branch always started from a success plan.

When a randomized sequence instead produced `plan.err == True`, the test still forced a success-style follow-up and failed in the test logic rather than in the DUT.

## 4. Fixes Applied

### 4.1 RTL

[`rtl/pt_malloc.v`](../../../rtl/pt_malloc.v)

- split command handling into:
  - decode-only request fields
  - allocation candidate computation
  - final command-side decisions
- removed the `cmd_a_len/cmd_b_len <-> a_alloc_ok/b_alloc_ok` combinational feedback path

[`rtl/pt_dispatch_v2.v`](../../../rtl/pt_dispatch_v2.v)

- introduced local mem-kind constants to reduce width/lint noise on directly related logic

[`rtl/pt_md_v2.v`](../../../rtl/pt_md_v2.v)

- used local mem-kind constants consistently to clean up directly related width/case noise

### 4.2 cocotb Environment / Model / Tests

[`sim/cocotb/tests/pt_blackbox_env_v2.py`](../../../sim/cocotb/tests/pt_blackbox_env_v2.py)

- restored `expected_dma_loads` cleanup after error responses
- added pending-plan finalization on `ctrl_resp`
- added a short export-side wait window to eliminate the same-cycle `ctrl_resp` / `m_dma_req` race

[`sim/cocotb/tests/pt_model_v2.py`](../../../sim/cocotb/tests/pt_model_v2.py)

- moved allocator pointer advancement to:
  - `commit_success`
  - `commit_load_success`
- added planned next-pointer state to `ExecPlan` and `LoadPlan` so failed transactions would not corrupt future capacity accounting

[`sim/cocotb/tests/test_pt_randomized_cases.py`](../../../sim/cocotb/tests/test_pt_randomized_cases.py)

- when `plan.err == True`, the test now closes out directly on the error response instead of forcing `wrong_tuser`, `export_error`, or success-only follow-up paths

## 6. Follow-Up Parameterization

Later on the same day, PT gained independent A/B/M bank-depth parameterization:

- `A_BANK_DEPTH`
- `B_BANK_DEPTH`
- `M_BANK_DEPTH`

The M store was no longer artificially tied to `A_BANK_DEPTH`.

The cocotb default profile became:

- `A_BANK_DEPTH = 8`
- `B_BANK_DEPTH = 16`
- `M_BANK_DEPTH = 16`

That better matched B-side reuse pressure and `MATADD` C-tile traffic.
