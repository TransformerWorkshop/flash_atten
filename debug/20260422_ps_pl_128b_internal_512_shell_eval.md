# 2026-04-22 PS-PL 128b / Internal 512b Shell Cost Model

## Summary

- Script: [`scripts/ps_pl_shell_cost_model.py`](../scripts/ps_pl_shell_cost_model.py)
- Wide measured anchor: `app/pt_tiled_gemm/out/multitile_sweep_pt_dma_top_v3_icarus_compact.json`
- Strict all-128b measured anchor: `app/pt_tiled_gemm/out/multitile_sweep_pt_dma_top_v3_128b_strict_icarus_compact.json`
- Internal PT geometry kept at wide `16x16`, `DATA_WIDTH=32`, `A/B/M-export lanes = 16`, `M-write lanes = 16`.
- Scenario matrix: `freq_ratio in {1x, 2x}` x `channels in {1,2,4}` x `{no_reuse, reuse_ab, reuse_ab_m_forward}`.
- Shape labels in this note use `MxNxK` shorthand, while the script CLI remains `--m --k --n`.
- Reuse ladder semantics:
  - `no_reuse`: `reuse_a=1`, `reuse_b=1`, `forward_m=off`
  - `reuse_ab`: `reuse_a=n_tiles`, `reuse_b=m_tiles`, `forward_m=off`
  - `reuse_ab_m_forward`: `reuse_a=n_tiles`, `reuse_b=m_tiles`, `forward_m=on`
- `forward_m=off` still writes the final output once, and additionally pays intermediate partial-M traffic; `forward_m=on` suppresses that intermediate traffic only.
- Important limitation: current RTL does **not** support multi-tile retained-M reuse, so any `forward_m=on` benefit here is an architectural projection, not current behavior.

## High-Level Takeaways

- `16x16x32` best projected shell point is `2x-4ch-reuse_ab_m_forward`: `82-90` cycles vs wide `82` and strict `218`.
- `32x32x32` best projected shell point is `2x-4ch-reuse_ab_m_forward`: `218-250` cycles vs wide `218` and strict `708`.
- `32x64x64` best projected shell point is `2x-4ch-reuse_ab_m_forward`: `529-593` cycles vs wide `529` and strict `1533`.
- `64x64x64` best projected shell point is `2x-4ch-reuse_ab_m_forward`: `1449-1577` cycles vs wide `1449` and strict `4877`.
- `1x x 1ch` is insufficient for every fixed shape, even with full reuse.
- Matching raw supply ratio (`1x x 4ch` or `2x x 2ch`) is necessary but not sufficient on larger shapes; without A/B reuse and M forwarding, transport still dominates.
- For long cases, the first credible shell operating points are `reuse_ab_m_forward` with either `1x x 4ch` or `2x x 2ch`; `2x x 4ch` only tightens the worst-case bound further.

## Conclusion

- A `128b -> 512b` shell is viable only when the external supply is increased by either channel parallelism, frequency ratio, or both.
- Small shapes can tolerate pure shelling once supply ratio reaches `1.0`, even without reuse.
- Large shapes (`32x64x64`, `64x64x64`) still need real A/B reuse, and the cleanest projected points additionally require `forward_m=on` to avoid intermediate partial traffic.
- For the fixed cases here, the practical envelope is:
  - `1x x 1ch`: never enough
  - `1x x 2ch` / `2x x 1ch`: useful only for the smallest cases
  - `1x x 4ch` / `2x x 2ch`: first serious operating points
  - `2x x 4ch`: mostly buys tighter worst-case bounds, not a new qualitative regime
- Because current RTL does not implement multi-tile retained-M reuse, these `forward_m=on` cases should be treated as architecture guidance for a shell-plus-local-reduction design, not as a promise about the current PT implementation.
